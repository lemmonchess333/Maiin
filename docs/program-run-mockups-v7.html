Tropos · Programme + Run · v7 final

4-tab Programme · Today | Schedule | Lift | Run

Restructured around ChatGPT's 4-tab proposal after verified code findings. Programme becomes a tabbed interface where each tab has a distinct purpose: Today = what to do right now, Schedule = operational week management, Lift = current lift programme preserved, Run = race-prep / structured run plan hub. Three P0 prerequisites must ship before the tabs work correctly.

Why we pivoted from the footprint switcher

v3-v6 footprint switcher handled mode switching but couldn't cleanly surface doubles days (lift + run same day). A coral dot on a lift circle says "there's also a run" — but there was no clean view that shows both modalities together at once.

v7 4-tab architecture introduces a Today tab that natively stacks both today's lift and today's run when a day is a "Both" day. Schedule tab handles the operational week (moving, swapping, skipping). Lift + Run tabs preserve the per-modality detail views.

The footprint icon top-right of Programme is now a quick-shortcut to /run (ad-hoc setup). Tabs handle planning. Footprint handles execution.

P0 prerequisites · must ship before the tabs are usable

All three are verified bugs in the current code, surfaced by ChatGPT's review. None of the tab UI works correctly without them.

1

Scheduler must support Both days

Current bug: runScheduler.ts:54, 148 caps run days at 7 - liftDayCount and excludes lift days. Cannot produce true doubles.
Fix: Drive scheduling from weekSchedule directly. runEligibleDays = weekSchedule.filter(d => d.type === 'run' \|\| d.type === 'both'). Without this, the Today tab's stacked-cards layout is fiction.
2

Route runs by scheduled identity

Current bug: RunCTACard.tsx:21-32 uses /run?template=tempo-id. Two tempo runs in the same week are indistinguishable.
Fix: Add scheduledRunId field to ScheduledRunDay. All run CTAs route with ?scheduledRunId=...&source=.... RunSummary completes the exact scheduled instance, not just "any tempo this week."
3

Move active-plan state out of Settings

Current bug: TrainingSection.tsx:87-333 owns 5 active-plan controls (weekly schedule, run mode, race goal, race progress, weekly overrides). Wrong place.
Fix: Migrate to Programme Schedule tab (weekly schedule) + Run tab (run mode, race goal, race progress, overrides). Settings keeps defaults only (units, audio, shoes, notifications).

Build phasing · 7 days total

P0 prerequisites first. Then the 4-tab Programme. Then edge states. Each phase shippable independently.

Phase Work Days Acceptance
P0 Fix scheduler — drive from weekSchedule with Both day support 0.75 A "Both" day in weekSchedule produces a scheduled run on that lift day
P0 Add scheduledRunId field + route all run CTAs by it 0.5 RunSummary completes the exact scheduled instance, not just "any tempo this week"
P0 Move TrainingSection controls to Programme Run tab + deep-link Settings 0.75 Settings no longer contains race goal form or weekly run overrides
P1 Add segmented control to Program.tsx: Today | Schedule | Lift | Run 0.5 Tabs switch the content area; URL state persists tab choice
P1 Build TodayTab.tsx with single / doubles / rest / completion states 1.0 Doubles day shows lift card + run card stacked
P1 Build ScheduleTab.tsx with the 7-day operational list 1.0 Move / swap / skip work end-to-end; past-week navigation works
P2 Build RunTab.tsx with race strip + this week's runs + plan controls 1.0 Race goal editor, run-days editor, full-plan modal all work
P2 Rename Goal to nutrition phase; move to Food 0.25 "Cut / Recomp / Lean Bulk" appears in Food, not Programme
P3 Run mismatch reconciliation UX 0.5 Off-plan runs save without auto-completing planned sessions
P3 Race elapsed states + completion celebration 0.75 Race date passes → cleanly resolves to complete or no-show
Order matters
Ship P0 first (scheduler + routing + settings migration). These are bug fixes, not new features — without them, the 4-tab UI is built on broken foundations. Doubles dots, scheduled-run identity, and active-plan ownership all depend on the P0 work landing first.
