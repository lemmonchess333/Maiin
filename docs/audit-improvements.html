Highest-impact improvements

Critical Fix the E2E suite blocker.

npx playwright test fails before running tests because test.use({ ...devices['iPhone 14'] }) is inside a describe group. Move device config to a project, top-level test scope, or separate test file.

High Replace template README with production docs.

The README still opens with generic Vite template content. Add app setup, env vars, Firebase/Capacitor flows, test commands, release steps, and operational runbooks.

High Wire native App Check.

Web App Check uses reCAPTCHA, but native Capacitor currently runs without App Attest / Play Integrity. This is a security and abuse-hardening gap.

High Harden AI scan quota and rate limiting.

Current quota/rate checks use read-filter-write patterns and fail open. Move to transactions/atomic increments and define fail-closed behavior for cost-sensitive paths.

Medium Make reminders durable and transparent.

Web reminders rely on setTimeout while the app is open, and reminder hooks mostly schedule the next occurrence. Add native repeating schedules and visible “next reminder” diagnostics.

Home / app shell

  • Lazy route loading and chunk retry recovery are strong, but global app crashes are logged with raw console.error. Consider routing these through structured error reporting so production crashes are searchable.
  • Build output indicates several large chunks: Firebase DB, charts, barcode, MapLibre, and app index. Deeper lazy loading for map/barcode/chart-heavy paths should improve first load and low-end mobile performance.
  • Add a small operator-facing diagnostics page or hidden route for version, build time, service worker state, Firebase project, and notification permission to speed up support/debugging.

Food

  • Preserve portion metadata from AI text parsing where available. Current NL save maps parsed items to a generic 1 serving, which weakens user review/edit clarity.
  • Consider proxying/caching Open Food Facts search server-side for reliability, timeout handling, analytics, and control over third-party API behavior.
  • Add explicit quick-add management: pin favorites, hide suggestions, and “show more” beyond the current capped heuristic list.
  • Add confidence/review UI for AI estimates before saving, especially for low-confidence meals or unusually high macros.
  • Add an offline queue indicator for food saves/deletes so optimistic UI does not hide failed persistence.

Run

  • Background tracking is the biggest product gap: the app stops GPS while backgrounded to save battery, then warns about gaps. Serious runners will expect native background location support with explicit permission education.
  • Add route-quality scoring: GPS accuracy distribution, gap count, rejected point count, and “route may be inaccurate” labels.
  • Pace inputs should validate format and show parsed values live before Start. Free-form pace text can silently fail to set a target.
  • Add clearer invalid-run messaging on discard. If a sub-threshold run is discarded immediately, explain why no confirmation appears.
  • Add recovery for accidental app close during an active run: draft state, elapsed time, and unsaved manual/treadmill distance.

Program / workout session

  • Add validation for workout set inputs: no negative values, realistic max reps/weight, decimal step rules, and warnings on huge jumps.
  • Add PR review/edit affordance before celebration. A fat-fingered value can currently feed PR detection immediately.
  • Confirm session rest timer initializes from Settings’ default rest time. If not, wire profile preference through the workout session.
  • Add “replace with equivalent movement” filters so substitutions preserve intent: vertical pull, hinge, squat, horizontal push, etc.
  • Add a session summary preview before final save: volume, duration, completed exercises, PRs, skipped sets, and notes.

Settings

  • Make every settings write visibly resilient: await/catch profile updates, revert optimistic local state on failure, and show a consistent inline or toast error.
  • Add tests around reactive TDEE persistence so changes to age/activity/phase update targets once and preserve custom calorie targets.
  • Privacy zones should support manual map/address entry, edit radius/name, and permission recovery guidance when geolocation fails.
  • Blocked-user display should prefer the public profile mirror rather than direct reads of private user documents.
  • Account deletion should explicitly clear local state/session and navigate after success, not rely only on a toast/auth observer.

Notifications

  • Add native repeating local notifications and reschedule on app foreground. Current web fallback is session-bound and not durable.
  • Add “send test notification” buttons for meal, workout, and streak reminders so users can verify device settings.
  • Show “next scheduled reminder” status for each reminder type.
  • Add consistent accessibility semantics to mini-switches, including role="switch", aria-checked, and labels.

Design system / accessibility

  • Continue migrating hand-rolled buttons to shared primitives: Button, IconButton, RunControlButton, Dialog, and BottomSheet.
  • Audit all tappables for 44px minimum touch targets, especially dense workout grids, set type controls, and mini-switches.
  • Standardize loading, disabled, aria-label, focus-visible, and destructive-confirmation behavior across feature surfaces.
  • Add automated accessibility checks for authenticated surfaces using seeded/mocked auth state, not just public/legal pages.

Data / security / rules

  • Move challenge seeding/admin writes server-side. Current authenticated write access is documented as an acceptable early-stage tradeoff, but malicious users can create junk challenge docs.
  • Add App Check enforcement once web and native token flow is verified.
  • Make AI quota updates transactional and avoid full AI response logging in production.
  • Add security tests for public profile mirrors, blocked users, challenge writes, activities count increments, and storage photo paths.

Suggested priority order

  1. Fix the Playwright E2E config so regression tests can run.
  2. Harden AI quota/rate limiting with transactions or atomic increments.
  3. Wire native App Check and then plan enforcement.
  4. Audit/migrate all hand-rolled tappables for touch target and accessibility consistency.
  5. Improve run background tracking and route quality diagnostics.
  6. Add stronger validation to workout set inputs and PR confirmation.
  7. Rewrite README/runbook for app-specific development and operations.
  8. Reduce large bundles by lazy-loading map, barcode, charts, and Firebase-heavy surfaces.
