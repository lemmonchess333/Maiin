stock photos. This doc is the workflow for the revived, upgraded pipeline —
and the record of the decision history, because this feature has now been
built, reverted, deleted, and revived once each. Read the history before

## The hard constraint (unchanged)

**A wrong demo is worse than no demo.** Image models get joint angles, grip
and limb counts wrong; a form guide showing bad technique is an injury +
credibility risk. So: generation is **offline + human-reviewed**, never
runtime; the app **always falls back** (free-exercise-db photos → muscle
diagram) when an exercise has no reviewed `media`.

## What's new in the revived pipeline

1. **Style anchor.** Every request includes
   `scripts/assets/tropos-figure-ref.png` — a crop of the app's REAL
   muscle-map figure (flat faceted grey vector, purple fills, dark ground).
   The prompt tells Nano Banana to pose _that_ figure. This is the direct
   answer to #1448's "different app" complaint: instead of describing the
   style and hoping, we hand the model the actual character.
2. **N-frame sequences** (`--frames`, default 4, max 6). Frames walk the
   range of motion top → bottom; each frame is generated by **editing the
   previous frame** (consistency chain). The in-app player ping-pongs the
   ordered frames (top → bottom → top = one full rep), with turnaround holds
   and crossfade already shipped (#1444/#1465) — more frames = smoother
   motion, zero player changes.
3. **QA contact sheet.** The script writes
   `public/exercise-demos/_preview.html` (gitignored) — an animated flipbook
   per exercise at the app player's cadence, next to the exercise's
   instructions. Review is minutes per batch.

## Workflow (operator — Codespaces works)

```bash
# 1. Preview the style on one lift first (uses ~frames× API calls):
GEMINI_API_KEY=… node scripts/generate-exercise-demos.mjs --only squat

# 2. Open public/exercise-demos/_preview.html — check style match, joints,
#    limb count, grip, ONE figure per frame, purple on the right muscles.

# 3. Iterate on failures:
GEMINI_API_KEY=… node scripts/generate-exercise-demos.mjs --only squat --frames 5

# 4. Scale to the pilot batch once the style is right:
GEMINI_API_KEY=… node scripts/generate-exercise-demos.mjs --limit 30

# 5. QA EVERY exercise in _preview.html. Delete bad ones, regen with --only.

# 6. Paste each PASSING id's printed `media:` snippet into
#    src/lib/exercises.ts (after that exercise's `regressions:` line — see
#    squat for the shape). Commit assets + wiring together.
```

The key is a free-tier **Google AI Studio** key (aistudio.google.com →
Get API key). The script paces requests and retries 429s.

## Consumer seam (already in the app — no per-exercise UI work)

- `Exercise.media?: string[]` — ordered frame paths (any count ≥ 1).
- `getExerciseDemo` prefers `media`; falls back to free-exercise-db photos.
- `ExerciseDemoPlayer` auto-plays any 2+ frames as a ping-pong crossfade
  flipbook (turnaround holds at the extremes); 1 frame renders static;
  reduced-motion users get a static 2-up of the extremes; if every frame
  fails to load the muscle diagram takes over.

So shipping a demo = generate → QA → set `media` → done.
