Different run type

You ran Easy 5km · today's plan was Tempo 8km

Mismatch reconciliation · save-time · planned ≠ actual

Status transition state machine

LEGAL:
planned → completed_exact   // exact template match
planned → completed_modified   // user reconciles mismatch
planned → completed_late   // done after scheduled date
planned → skipped   // user explicit skip
planned → race_no_show // race day + no run logged
planned → race_completed_unlinked // race logged separately
race_completed_unlinked → completed_exact // user manually links
DISALLOWED:
completed_* → planned   // no silent reverts
completed_* → skipped   // no retroactive skip
skipped → completed_*   // without explicit reconciliation
NOT STATUSES (in v7):
missed   // derived at view-time
moved   // metadata: movedFromDate / movedToDate
freeform_extra   // lives on saved run's planMetadata.planSource

Existing-user migration UX

When a TestFlight/beta user opens Programme post-deploy for the first time, they get a one-shot Coachmark explaining the new tabs. Lazy backfill silently populates `weekSchedule` if missing. Migration is shape-repair only — never regenerates plans.
