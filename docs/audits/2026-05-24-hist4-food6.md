The lock-then-ship pattern is working — most locked items DO get shipped, and the remaining gaps are either small punch-list items or genuine architectural questions that need fresh thinking, not heuristic completion.

### Recurring blocker: S4d backend

Soc5 #15 + Food6 F3 are both blocked or partially blocked on the same thing — the `globalRestrictedUids` collection + Cloud Function strike accounting that S4d/e specs but does not yet implement. If you do a single half-day-to-full-day S4d arc later, **two locked decisions unblock simultaneously**, plus any future moderation work has a real backing store.

### Recurring deferred-item pattern

Across all four decisions, the items most often deferred are: pull-to-refresh, lazy-load tuning, deep-link parameter reconciliation, and chart drill-downs. These all share a common signature — they're _real UX value_ but each one alone is ~3-5 hr of work, and they keep showing up across surfaces. Consider whether a single "Page IA polish sprint" that tackles pull-to-refresh + deep-link contract reconciliation across Home/Social/History/Food in one go would be cheaper than fixing each in isolation.
