# Sub2 audit — 2026-05-24

**Scope:** Sub2 (Pro feature scope) locked decision vs. current
implementation. Lock row lives in
`.claude/plans/programme-run-followups.md` (line 535).

## Headline

Sub2 was ratified but the underlying machinery doesn't match the
lock's premises. Two layers below Sub2 are out of sync:

1. The `featureAccess` flag map in `subscription.ts` is mostly
   cosmetic — 6 of 7 flags are never read.
2. F1b (which Sub2b "keeps unchanged") was never actually
   implemented as locked.

Sub2's user-facing intent ("PI moves to free, Pro narrows from 6→4
keys") is mostly already true _by accident_ — because the gating
mechanism Sub2 targets isn't load-bearing.

## Findings

### 1. `featureAccess` map is cosmetic — 6 of 7 flags never read

Grep across `src/` (excluding tests + the definition itself):

- `phaseModes` → read once (`src/pages/Program.tsx:69`)
- `aiAdjustments`, `plateauDetection`, `performanceInsights`,
  `workoutLogging`, `foodLogging`, `basicSummary` → **zero callsites**

Sub2's narrowing from 6→4 Pro keys + flipping plateau/PI to free is
technically a no-op because nothing reads the flags. Gating happens
via direct `isPro` checks and `<ProGate>` wrappers in components —
the map is decorative.

### 2. F1b implementation drift — Sub2b ratifies a fiction

**F1b locks** (lines 489, F1b body):

- Daily reset (user's local midnight)
- Separate `text_ai` and `image_ai` counters in `rateLimiter.js`
- Free: 10 text/day + 0 image/day
- Pro: 100 text/day + 100 image/day (server-side abuse-protection caps)
- Trial users bypass entirely
- Settings shows daily usage pill

**What ships** (`functions/rateLimiter.js` + `src/hooks/useScanUsage.ts`):

- **Monthly** reset (`currentMonth = YYYY-MM`)
- **Shared** counter at `scanUsage/{uid}` — `analyzeFood` and
  `analyzeFoodText` both increment it
- Free=10/month, Pro=300/month
- **Image AI is NOT blocked for free users** — free users can spend
  their 10/month on image AI (lock says image=0/day for free)
- Trial bypass works (`isUnlimited = isPro || isInTrial`) — only
  thing aligned

Sub2b ratifies F1b but F1b was never implemented. The drift is its
own implementation slice — not bundled with Sub2's audit follow-ups.

### 3. `phaseModes` flag is wired to the wrong surface

Sub2c pin #4 describes `phaseModes` as gating day-type-specific
macros (`phaseNutrition.ts` output). But `src/pages/Program.tsx:69`
uses `!features.phaseModes` to derive `phaseLocked`, which gates the
program-configuration buttons (Configure plan / Settings / Refresh).
Day-type-specific macros are computed by
`src/hooks/useEffectiveTargets.ts`, which doesn't consult the flag —
so free users get day-type macros today regardless of tier.

### 4. Sub2c pin #3 over-gated adaptive TDEE — FIXED 2026-05-24

**Lock:** "free users see TDEE number but not 'Adjusted X kcal based
on 7-day trend' callouts; tap-to-learn → ProModal explains adaptive
TDEE".

**Pre-fix:** `AdaptiveTDEECard` was wrapped wholesale in
`<ProGate featureKey="adaptive_tdee">` — free users saw only the
blurred preview behind an "Unlock with Pro" overlay button.

**Fix:** PR-pending — wholesale wrapper removed; per-section gating
inside the card. Free users see the TDEE number in the collapsed
header; expanded view replaces adaptive callouts with a single inline
unlock CTA → opens ProModal with `featureKey="adaptive_tdee"`. Pro
users see the full card unchanged. Five TDD'd tests pin the contract
in `src/components/__tests__/AdaptiveTDEECard.test.tsx`.

### 5. Sub2c pin #4 not implemented — DEFERRED

**Lock:** "Free users get FIXED daily macros (one ratio for all
days); Pro users get day-type-specific macros".

**Current:** `useEffectiveTargets.ts` runs day-type macro logic for
everyone — no tier check.

**Deferral rationale:** Implementing this is a real UX regression for
current free users (who get day-type macros by accident today). The
lock specifies the post-launch shape, but with one pre-launch user
and zero free-tier signal, validating the lock empirically is
impossible. Defer until first real free-tier traffic; revisit then
with usage data.

### 6. Only one real `<ProGate>` wrapper in the app

Sub2d implies lock icons on adaptive TDEE tooltip, macros day-type
indicator, and image-AI camera shutter. Only adaptive TDEE has a
gate. The macros indicator and image-AI shutter aren't gated at the
UI layer — the macros surface is ungated (per finding 3) and image-AI
is server-rate-limited via the shared quota (per finding 2).
