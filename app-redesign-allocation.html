1 · App architecture

Recommended surface ownership

Each tab should have a single mental model. If a feature breaks that model, either move it or expose it only as a small summary with a link.

🏠

Home

Daily command centre: today’s priority, next action, energy status, and lightweight nudges.

🏋️

Programme

Plan ownership: weekly schedule, strength, running, race prep, swaps, rebuilds.

👟

Run

Pre-run cockpit and live execution: prescribed run first, free choices second.

🍽️

Food

Nutrition execution: targets, meal logging, phase, day-specific fuel explanation.

👥

Social

Community: feed, crews, challenges, comments, shareable milestones.

📊

History

Evidence: analytics, PRs, trends, badges, completed run and workout details.

⚙️

Settings

Defaults, account, privacy, notifications, support, and compact links to manage workflows elsewhere.

2 · Reallocation

4 · Design rules

Rules to prevent clutter

These constraints let the app gain depth without turning every screen into a dashboard.

01

One hero per screen

Home has today. Programme has plan. Run has the prescribed run. Food has energy. Settings has account summary.

02

Cards show state

Cards should explain status and offer one obvious action, not expose every possible control inline.

03

Sheets handle decisions

Use bottom sheets for run swaps, target edits, cue settings, active shoe choice, and plan adjustments.

04

Full screens handle flows

Race plan creation and programme rebuilds need focused flows with previews, not inline settings clutter.

05

Accent, don’t flood

Use semantic colour as a cue. Keep surfaces neutral and let primary actions carry the strongest colour.

5 · Before / after

What the user feels

Before

Powerful but misplaced

  • Settings feels like a planner, not just preferences.
  • Run asks users to choose manually even when a plan exists.
  • Programme under-represents running plan intelligence.
  • Food sends target changes away to Settings.
  • Home risks becoming a stack of equal-weight cards.
After

Intentional and calm

  • Settings becomes tidy defaults and account controls.
  • Run leads with the prescribed run and keeps options secondary.
  • Programme owns weekly structure, race prep, and plan edits.
  • Food owns targets in a native bottom sheet.
  • Home shows only today’s next best action.
6 · Build sequence

Ship it in the right order

Do not rip workflows out of Settings before their new homes exist. Fix trust issues first, then redesign.

P0

Correctness and trust fixes

Race template by distance, distance-specific minimum dates, no half-configured race prep, edit/delete/rebuild actions, consistent date copy.

Foundation
P1

Programme → Running

Create the real home for race prep: summary card, this week’s runs, swap sheet, full plan, and adjust flow.

Plan hub
P2

Plan-aware Run setup

Make the prescribed run the hero, keep free run types as secondary, and expose voice cues as per-run controls.

Execution
P3

Food-native target management

Replace the Settings gear jump with a nutrition targets sheet and TDEE/phase controls inside Food.

Nutrition flow
P4

Settings cleanup

Convert heavy sections into compact summary rows that deep-link to Programme, Food, Run, and Workout where appropriate.

Polish

Designed as a standalone planning artefact for the Tropos app redesign discussion.
